1Entropy — randomness is the whole game

A Bitcoin wallet is really just a very large secret number. If that number is random enough, nobody can ever guess it — there are more possible keys (2256) than atoms in the observable universe. If it's not random — if it was made with a weak or predictable source — an attacker can regenerate it and take the coins.

This is exactly how the early browser wallets of ~2014 were broken: they used weak randomness. Olesia draws its 256 bits from your operating system's cryptographic random generator (crypto.getRandomValues) — the vetted source — and optionally stirs in mouse movement and dice as defence-in-depth (a hash of many inputs is strong if any one is strong).

2The seed phrase (24 words)

That giant random number is encoded as 24 English words (the BIP-39 standard, from a fixed list of 2048 words). The words are your wallet — anyone with them controls the coins, and there is no "reset password." The last word includes a checksum, so a typo is usually caught.

An optional passphrase (the "25th word") is a secret applied on top: you then need both the words and the passphrase. Lose it and the funds are gone — there's no recovery.

Save it on paper, in order. Never screenshot it, cloud-sync it, or type it into a website you don't trust. A photo in your camera roll is a photo in someone's cloud.

3Private & public keys

From the seed, the wallet derives private keys. Each private key has a matching public key, computed by one-way maths (elliptic-curve multiplication on the secp256k1 curve): easy to go private → public, effectively impossible to reverse. You sign a transaction with the private key to prove you own the coins; anyone can check the signature with the public key.

Signing must use a fresh, unpredictable value each time (a "nonce"). Reusing or predicting it leaks the private key — another classic way wallets were drained. Olesia signs with RFC-6979 deterministic nonces, which makes that mistake impossible.

4Addresses & script types

An address is just a friendly encoding of a rule that says "to spend these coins, satisfy this script." Different script types are different rules — and the same seed produces a different address for each type. That's the best way to understand what an address really is: not a place, but a lock.

The museum, oldest to newest:

  • P2PK — Satoshi's original. Pays straight to a public key (⟨pubkey⟩ OP_CHECKSIG). It has no address — the output is the key. It's how the genesis block's coins are held, and because the key sits on-chain in the open, it's the classic quantum-resistance talking point.
  • P2PKH — the classic 1… address. Locks to the hash of a public key, so the key only appears when you spend.
  • P2SH-P2WPKH — SegWit wrapped in a 3… address for old-wallet compatibility.
  • P2WPKH — native SegWit (bc1q…). Cheaper fees; the default.
  • P2TR — Taproot (bc1p…). Schnorr signatures, better privacy, cheaper multisig.

5Transactions & UTXOs

Bitcoin has no "balance" field. Instead you own discrete chunks called UTXOs (unspent transaction outputs) — think of them as coins of odd denominations in your pocket. To pay someone, a transaction consumes some of your UTXOs as inputs and creates new outputs: one to the recipient, and usually one back to yourself as change (like getting change from a £20 note).

You can also attach a tiny OP_RETURN output — up to ~80 bytes of arbitrary data — to write a permanent message on-chain. Olesia lets you do exactly that.

6Fees

Miners include transactions that pay them, so you attach a fee, priced in satoshis per virtual byte (sat/vB). A bigger or more complex transaction costs more; a busier network needs a higher rate to confirm quickly. On testnets fees barely matter, which makes them a safe place to learn how fee choice affects confirmation time.

7Networks — practise for free

Bitcoin has several chains that share the same rules but use worthless coins for testing:

  • Testnet3 / Testnet4 — long-running public test chains (Testnet4 blocks can be erratic).
  • Signet — a test chain with regular ~10-minute blocks — the smoothest place to learn.
  • Mainnet — real Bitcoin, real value. Only step here once you understand the rest.
Every test network uses the same key maths as mainnet — so a wallet you build to practise is the real thing, just pointed at a playground.

8Hot vs cold — and the one rule

A hot wallet keeps keys on an internet-connected device (a phone, a browser tab). Convenient, fine for small amounts, but a compromised device — or a compromised website — can steal the keys. A cold wallet generates and signs offline, so the keys never touch a networked machine.

The subtle risk with any web wallet: the code is fetched from a server every visit, so you're trusting whoever runs that server. The defence is to download the cold generator, verify its published hash, disconnect, and run it offline — then you're trusting maths, not a server.

The one rule. Don't keep meaningful amounts in a hot/online wallet. For real value: cold-generate offline, verify the hash, back up on paper, and consider a hardware wallet. Olesia's online wallet is for learning and small amounts — on purpose.

9Backups done right

Your only real backup is the 24 words. Write them on paper (or steel), store them somewhere safe, and test the backup before you trust it — restore it into independent software and confirm you get the same address. Olesia's cold generator has a built-in check for exactly this. An untested backup is not a backup.

You can also export an encrypted backup file (scrypt + XChaCha20-Poly1305) and a watch-only descriptor (which can see your balance but cannot spend) — a safe way to monitor funds from an everyday machine.
